# 出题 Prompt · 把一句想法变成可判定规则

> 用法：把 `{{...}}` 替换成你的内容，整段发给一个顶级 AI。
> 这个阶段**不要写代码**。目标是把规则写到“两个人都能独立手算出同一个结果”。

---

你是 `{{GAME_ID}}` 的出题人。你的唯一任务是：把下面这个游戏想法，写成一份**可判定、可实现、可测试**的规则草案。

游戏名：`{{GAME_NAME}}`
原型/灵感：`{{INSPIRATION}}`
目标模式：`{{TARGET_MODE}}`（例如 1v1、2v2、1v4 非对称）
目标单局长度：`{{TARGET_LENGTH}}`（步/轮/波）
单步预算：`{{TURN_MS}}` ms CPU（首步 `{{FIRST_TURN_MS}}` ms）
信息模型偏好：`{{INFO_MODEL}}`（完全信息 / 部分信息 / 非对称）
一句话玩法：`{{ONE_LINE}}`

---

## 硬约束

1. 这是给 AI 写 bot 的回合制游戏，不是实时游戏。所有“同时”必须是“双方提交指令，引擎按固定顺序结算”。
2. 一个 bot 控制的单位数建议 3–4 个；如果是 1v1 决斗，必须说明为什么 1 个单位也足够深。
3. 必须有反拖延时钟：炸弹计时、涨水、缩圈、波次、检查点、终局计分，至少一个。
4. 所有随机必须由 seed 决定；不允许“每局随机”“裁判临时决定”。
5. 所有动作必须能用整数/定点表示；不允许依赖浮点物理。
6. 所有“同时”必须有确定的结算顺序；不允许“看情况”。
7. 规则必须能用手算：给定一个小地图和两条指令，人能推出唯一结果。
8. 不要写代码。不要写 C++。不要写伪代码超过 20 行。

---

## 输出格式

严格按以下顺序输出。不要加“总结”“建议”“未来工作”之类的章节。

### 1. `RULES.md` 草案（12 节）

按这 12 节写，每节都要有内容；不确定的地方写 `TODO:`，不要猜：

1. 概述：一句话、模式、单局长度、核心循环；
2. 地图与初始状态：尺寸、格子类型、出生点、对称性、地图池；
3. 单位：数量、HP、移动、武器、弹药、特殊能力；
4. 一局的流程：轮/步/阶段、先后手、换边、加时；
5. 一步的结算顺序：编号列表，精确到“先移动还是先开火”；
6. 动作空间：每个单位每步能做什么、消耗什么、非法条件；
7. 信息模型：谁能看到什么、隐藏什么、最后已知位置/声音/ ping 的寿命；
8. 胜负与平局：提前结束、终局计分、tiebreak 顺序；
9. 反拖延：什么机制保证比赛不会无限拖；
10. 协议草案：`INIT` / `TURN` / 输出 / `RESULT` 的行格式；
11. 边界判定：至少 25 条“如果……那么……”；
12. 参数表：所有数值、默认值、可调范围、影响。

### 2. 状态机

用表格列出：

| 状态字段 | 类型 | 谁可见 | 何时更新 |
|---|---|---|---|
| ... | ... | ... | ... |

然后列出每步的状态转移：

```
step(t):
  s1 = validate(orders)
  s2 = move(s1)
  s3 = fire(s2)
  ...
```

### 3. 边界问题清单

至少 25 条，每条一句话，格式：

- `Q: 两个单位同时进入同一格，怎么处理？`
- `A: 都不动。`

不要只写问题不写答案。

### 4. 参数表

| 参数 | 默认值 | 范围 | 影响 | 备注 |
|---|---|---|---|---|
| ... | ... | ... | ... | ... |

### 5. 实现风险

列出 5–10 个“这个规则最容易实现错/最容易不平衡”的点，每条给一个缓解方案。

### 6. 未决问题

列出你无法从现有信息推出的问题，每条给出 2–3 个可选方案和推荐方案。不要替我做决定，但要给推荐。

---

## 设计检查

写完后，逐条自检：

- [ ] 每个动作都有非法条件；
- [ ] 每个“同时”都有固定顺序；
- [ ] 每个随机源都能追溯到 seed；
- [ ] 每个单位都能在 50 ms 内做出合法决策；
- [ ] 没有“玩家需要看完整状态但只能看一部分”的矛盾；
- [ ] 没有“谁先点谁赢”的实时机制；
- [ ] 没有“无限循环/无限拖延”的可能；
- [ ] 25 条边界用例覆盖：同时移动、同时死亡、目标格被占、资源不足、超时、非法、平局、换边、终局；
- [ ] 参数表里的每个值都有理由，不是拍脑袋。

如果任何一条不满足，先修规则，不要进入实现。
