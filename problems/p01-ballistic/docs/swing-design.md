# P01 评分 v2：胜率排名层 + 操作质量层（operation_swing 设计）

> 日期：2026-11-10（rating-design.md 定稿当晚的续篇）。
> 回应提问方的三个直觉：**座位调整**（奖励差位置打得好、惩罚好位置打得差）、
> **operation_swing**（操作带来的增益/减益）、**借鉴 HLTV 3.0**。
> 每个直觉本轮都用现有回放做了实测，结论先行：
>
> 1. **座位调整：直觉对，做法必须改**。加性座位块模型（win ~ bot + seat）实测
>    **不可用**——座位好坏**因 bot 变号**，且模型让成对 CI 宽度翻倍（§1.1）。
>    座位补偿的正确形态是「座位诊断表」（§1.3），不是排名修正项。
> 2. **operation_swing：方向正确**。「浪费操作」以**命中率 + 资源效率**为载体
>    进入（§2.2）。
> 3. **HLTV 3.0：借鉴原则，不抄公式**（§3；其细则凭记忆，未联网核验）。
>
> ⚠️ **【2026-11-10 晚更正】** 本文第一版 §1.3 曾把 `bad`（非法动作）当成
> 座位劣势的「主操作载体」——**那是死后伪影，结论错误，已重写**。
> 提问方当时就质疑「seat0 赢的时候 seat1 干什么都是 bad」，实测比这更极端：
> **存活期 bad = 0.00%**（两个数据集、4 bot、约 3 万存活回合零例外）；
> 全灭后席位仍交 `N WAIT`（点名死虫）才被记 bad（76-92% 回合）。
> `bad` 整列只是**灭绝时长的代理**。详见 §1.3 重写版。
>
> 本文档全部读数的复现命令在 §6；脚本在 评测过程记录（未随仓库发布）。

## 1. 本轮实测（三个实验）

### 1.1 座位块模型：加性调整不可用（且代价是分辨力）

动机：24 排列把座位暴露**精确**配平（每个 bot 每个座位恰好 6 次/图），所以
排名的点估计本来就不需要座位调整；加性座位块（`P(胜者=i) ∝ exp(u_i + s_seat)`）
唯一的可能收益是**方差缩减**（随机化区组的思想）。实测（`seatblock_explore.py`）：

| panel | A 平模型 CI 宽度 | B 座位块 CI 宽度 | held-out Δlogloss（B−A） |
|---|---:|---:|---:|
| evruns2（288 局） | 13.1pp | **25.8pp（翻倍）** | −0.038（n.s.，2/12 图胜） |
| evruns（144 局） | 15.4pp | **41.1pp（2.7 倍）** | −0.174（n.s.，4/6 图胜） |

⇒ **分辨力不升反降**。原因见下条：加性模型的假设（座位效应对所有 bot 同向
同幅）不成立，misspecification 的代价 + 8 参数的估计噪声吃掉了全部区组收益。

### 1.2 bot×座位胜率矩阵：座位好坏因 bot 变号

| bot \ seat | 0 | 1 | 2 | 3 |
|---|---:|---:|---:|---:|
| **evruns2（288 局）** | | | | |
| typhon | 72% | 51% | 53% | 74% |
| tide_hard | 43% | **11%** | 21% | 35% |
| tide_easy | 17% | 6% | 4% | 12% |
| random4 | 0% | 0% | 0% | 1% |
| **evruns（144 局）** | | | | |
| tide_normal | 47% | 25% | 39% | **72%** |
| tide_hard | 42% | 25% | 31% | 61% |
| tide_easy | 17% | 6% | 6% | 28% |

⇒ seat 3 对 tide_normal 是最好的位置（47%→72%）、对 typhon 无所谓
（74%→74%）、对 tide_hard 反而不如 seat 0（43%→35%）。**「好位置」不是
全局量，是 bot×位置的函数**——所以「按座位好坏给全局修正」在原理上就不成立。
这也解释了 §1.1 里加性模型拟合出的 s 与边际座位份额矛盾。

### 1.3 bot×座位操作画像：bad 是死后伪影，座位机制是「承伤更多 + 交易更快 + 死得更早」

**第一版结论作废**：初版把 `bad/局`（内席 5.25 vs 外席 0.83）读成「浪费操作
是座位劣势主载体」。提问方质疑「seat0 赢的时候 seat1 干什么都是 bad」，
实测验证（`bad_endogeneity.py`）比质疑还极端：

| bot | 存活期 bad/回合 | 全灭后 bad/回合 |
|---|---:|---:|
| tide_hard | **0.00%**（n=7101） | 81.2%（n=1085） |
| typhon | **0.00%**（n=7798） | 75.8%（n=388） |
| tide_easy | **0.00%**（n=6712） | 83.5%（n=1474） |
| random4 | **0.00%**（n=4725） | 91.7%（n=3461） |

（evruns 144 局同分布；`bad>0` 的回合 5581/5581 指令均为 `N WAIT`。）

⇒ **活着的虫从不交非法指令**（至少这批 bot）；全灭后的席位每回合仍交
`N WAIT`（点名死虫）被引擎记 bad。`bad/局` = 死后剩余回合数的代理，
「bad 最多 == 最先灭绝」在 288/288 局成立是同义反复。
「typhon 对浪费操作鲁棒」的故事随之作废——typhon 内席 bad 少只是因为它
很少死透。

**修正后的座位机制**（`seatprofile.py` 更正版，evruns2）：

| seat | 承伤/局 | 胜率 | （各 bot 灭绝轮：内席早 2~4 轮） |
|---:|---:|---:|---|
| 0 | 276.2 | 33.0% | |
| 1 | 289.3 | 17.0% | |
| 2 | 287.7 | 19.4% | |
| 3 | 267.8 | 30.6% | |

内席承伤约 **+5~8%**、双边接敌**交易更频繁**（tide_hard 内席 dealt 反而更高：
411.7 vs 379.8，且有效轮/局持平 ⇒ 单位时间输出更快）、**死得更早**。
（承伤为 2026-11-11 首回合口径修正后的读数；旧口径低估首回合承伤，
夸大了内外差距为 +10%。）
与 known-issues.md「内席劣势 = 直击/两面夹击」的既有结论一致（混合场上量级较小）。
dealt/hit_rounds 跨座位平坦 ⇒ 座位不改变火力，改变的是**暴露面与节奏**。

⇒ 对 swing 设计的直接含义：**「浪费操作」的正确载体是命中率与资源效率**
（§2.2），不是 `bad`；`bad` 保留一列「存活期 bad」作为未来 bot 的
**探测器**（当前恒 0，若有 bot 活着乱交指令，这列会立刻响）。

## 2. 设计

### 2.1 排名层（Layer 1）：维持 rating-design.md，明确不做座位调整

- 主分 = panel 内胜率；部分序榜单；图块 bootstrap。
- **不做**任何形式的座位修正（§1.1 实测代价；§1.2 原理不成立）。
  24 排列的精确配平已经实现了「好位置赢不算你强、差位置赢更算你强」的
  **机会公平**；排名层到此为止。
- 座位信息不进排名算术，但进**诊断输出**（§2.3）。

### 2.2 质量层（Layer 2）：operation_swing 组件表

每个组件 = 每 bot 每局一个数，全部从回放事件流提取，**局内归一**
（share 或 z-score，抗图长/节奏/风的混杂），报告时多列并列。

| 组件 | 定义 | 数据来源 | 精度 |
|---|---|---|---|
| `dmg_out` | 造成伤害（每回合 `dealt` 增量累计） | turn.dealt | **精确** |
| `dmg_in` | 承受伤害（hp 减量） | turn.worms[].hp | **精确** |
| `kills` | 击杀（虫 alive 翻转）；多攻击者按该回合伤害增量分摊 | turn.worms[].alive + dealt 增量 | 时点精确，归因近似（v1） |
| `assists` | 对「被别人收掉的虫」的伤害贡献 | 同上 | **近似**（v1 只用单攻击者回合；v2 用 oracle 逐弹道归因） |
| `hit_rate` | **命中率** = 造成伤害的回合数 ÷ 出手回合数（每席每轮 ≤1 出手、弹着同回合结算） | turn.shots + dealt 增量 | **精确**，浪费操作的主载体 |
| `bad_alive` | **存活期**非法动作数（排除全灭后的 WAIT 伪影） | turn.bad × 存活判定 | **精确**；当前 4 bot 恒 0，作为未来 bot 的探测器保留 |
| `res_eff` | 资源效率 = grenades/drills 消耗 ÷ dmg_out | turn.worms[].grenades/drills | **精确**（「浪费手雷」以效率形式进，不直接扣分） |
| `shots` | 出手量（分弹种计） | turn.shots | **精确** |
| `ext_time` | 灭绝轮 | worms[].alive | **精确** |
| `first_blood` | 首次造成伤害的轮次 | dealt 增量 | **精确** |

设计要点（对应提问方的原始想法）：

- **「浪费 grenade 扣分」→ 以 `res_eff` 效率形式进入，不拍扣分系数**。
  原因：压制性/封走位的空枪可能是理性行为，直接扣分会惩罚合理的 zoning；
  让权重由 §2.2 的回归去决定——如果浪费真的负相关于赢，它会自动拿到负权重。
- **权重不手拍**。composite（如果出）的权重 = 回归系数：
  `P(bot 赢该局) ~ 组件向量`，按 bot×局 观测拟合，报告系数及其 CI。
  这是 HLTV 一族的做法（他们 2.0 的 impact 权重同样来自对回合胜率的回归）。
- **v1 默认只出组件列，不出 composite**。composite 要过 §2.4 的门。
  唯一的例外是**单数字画像 PR**（rating-design.md §3.5）：只用两个符号稳定组件
  `dmg_out_share`/`dmg_in`、按场几何均值归一到 1.00，属「允许的、受限的
  composite」；kills/assists/hit_rate 仍不进（符号跨场翻面）。
- **座位不进组件的修正项**：局内归一之后，同局四席共享同一张图、同一风程序，
  「在 seat 1 打出高 dmg_out」自然就体现了「差位置打得好」；显式座位修正
  被 §1.1/§1.2 否决。

### 2.3 座位诊断表（新输出物，替代「座位调整」）

每 bot × 每座位一行：胜率、bad/局、dmg_out/局、灭绝轮（§1.3 的表）。
它直接回答「谁在哪个位置怎么输的」，是提问方「分析具体操作」的落地形态。
排名层消费它吗？不。它是给人看的诊断，也给 bot 作者看的改进靶点。

### 2.4 验证门（composite 启用条件，复用 rating-design.md §7 的纪律）

swing composite 想成为单一「质量分」，必须：

1. 跨 panel（≥3 阵容）held-out：swing 画像对**下一局**胜负的预测增量
   显著为正（按图块 bootstrap，95% CI 不含 0）；
2. 系数方向稳定（bad/res_eff 为负、dmg_out 为正）且两个独立 panel 同号；
3. 换 seed 复现。

**【2026-11-11 首轮实测】**（评测过程记录（未随仓库发布），5 panel × 288/144 局，
读数 评测过程记录（未随仓库发布））：

| 检验 | panel A（四强） | panel B（中坚） | panel C（跨档） | T（TIDE） | T2（TYPHON） |
|---|---:|---:|---:|---:|---:|
| T4 跨局 Δlog-loss | **−0.050\*** | **−0.027\*** | **−0.030\*** | **−0.054\*** | **−0.060\*** |
| T2 dmg_in 系数 | −3.51 | −3.45 | −3.45 | −2.78 | −3.02 |
| T2 dmg_out_share 系数 | +1.20 | +0.76 | +1.50 | +0.19 | +0.58 |
| T3 composite↔win% ρ | 0.40 | 0.80 | 0.95 | 1.00 | 1.00 |

（\* = 95% CI 不含 0；T1 同局刻画在 5/5 panel 达 0.04~0.11，有循环性仅作参考。）

**裁决**：
- **T4（门 1）5/5 通过**：swing 画像的跨局预测增量显著为正——**质量层
  组件表升级为「带效度证据的画像」**，`rating4` 输出接入获得依据。
- **T2（门 2）只过两条**：`dmg_in`（5/5 为负，−2.8~−3.5，**谁挨打谁输**）
  与 `dmg_out_share`（5/5 为正）方向稳定；`kills`/`assists`/`hit_rate`/
  `first_blood` 在 panel 间符号翻面（与 dmg_in/dmg_out_share 的共线性
  吸收有关）——**composite 单一分不开成，维持「组件列并列，不合成」**。
- **T3 弱场失效**（panelA ρ=0.40，近邻场 composite 排序会错）——
  再次确认质量分不进排名层。
- 附带教训：gate 首版把「座位」当成备选项（sb.index(sb[ws]) 给的是座位号），
  "T4 显著"是座位偏置漏进模型的伪影；修正为 canonical bot 下标后读数
  与生成日志逐字吻合（panelA 20.1/28.5/22.6/28.8）。同族 bug 三连：
  事件流工具的 bots[s]、gate 的 sb.index(sb[ws])——**凡经 seat 的
  分析一律先对「生成日志 vs 工具读数」再采信**。

### 2.5 已知风险（提前写明，防止未来误用）

- **风格混杂**：磨血型 bot 的 dmg_out 天然高于收头型（kill 效率低）。
  组件列分开看可以识别；composite 的回归权重部分吸收，但不完全。
  这是组件列默认并列、composite 过门才出的原因之一。
- **assist 归因的近似误差**（v1）：多攻击者回合按增量分摊会把「磨最后一丝血」
  误记一部分给大伤害者。v2 用 oracle（`public/oracle` 的 shot/trace 模式，
  与引擎逐 tick 一致）做逐弹道精确归因，代价是离线计算量。
- **跨场不可比**：局内归一只保证场内可比；不同阵容的 swing 不可直接比
  （与 win% 同样的限制）。

## 3. HLTV 3.0 借鉴清单（⚠️ 凭记忆整理，未联网核验，引用其思想而非配方）

| HLTV 3.0 的做法 | 我们的对应 | 是否采纳 |
|---|---|---|
| per-round 归一（不以总局数稀释） | 局内 share/z + 有效轮归一 | ✅ 采纳 |
| 权重来自对胜负的统计关系，非手拍 | P(win) ~ 组件回归 | ✅ 采纳 |
| 表现指数与胜负排名**分离**（rating 高 ≠ 赢比赛） | swing = 质量轴，win% = 排名轴 | ✅ 采纳（这是最重要的纪律） |
| 上下文调整（eco/save 轮降权） | 局内归一 + 座位诊断表 | ✅ 形式采纳 |
| 对手强度调整（vs top-10 视图） | 跨 panel 校准 | ⛔ 暂不（固定 4 席场内无意义，跨场比较本身未定义） |
| 具体 5v5 结构（队友/道具协同、KAST/trade 概念） | 不存在对应物 | ⛔ 不抄 |

不套用的根本原因：CS 是**两方零和**、回合内有明确对抗结构、有 scoreboard
语义；P01 是 4 方混战、回合异步（每轮只激活一条虫）、伤害归因藏在弹道里。
结构不同，公式级套用必然错位——但「归一、经验权重、表现与胜负分离」这三条
纪律是通用的。

## 4. 数据可行性总结

回放每 turn 已含：`shots`（弹道参数，含弹种）、`hp[4]`、`dealt[4]`、
`bad[4]`（非法动作——**注意死后伪影**，RULES §STATE 行说明）、
`worms[12]`（x/y/hp/grenades/drills/alive）、`wind`。§2.2 的组件里
8/10 **精确免费**；kills 归因 v1 近似；assist v1 粗近似（v2 需 oracle
逐弹道）。不需要改引擎、不需要 bot 配合，纯离线。

**地形破坏量（提问方问的「破坏方块数」）**：逐回合地形**不在**回放里
（`replay_grid` 只存初始 map）。两条路：
- v1 代理：grenades/drills 消耗 + 命中率（已在组件表）；
- v2 精确：引擎确定性 + 回放含完整指令日志与逐回合 `state_hash`
  ⇒ 可以**离线重放重算**（同 map/seed/mask 逐回合喂指令，读回 STATE+GRID），
  逐弹道归因破坏量、精确 assist。成本 = 每局一次引擎重放，可行。
