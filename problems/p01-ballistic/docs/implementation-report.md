# P01 · BALLISTIC · 实现报告

> 日期：2026-11-01

## 1. 为什么接着做 P01

P06/P07 都是格子游戏：位置是整数，移动是离散的，"确定性"几乎是免费的。

P01 不是。弹道是连续的，连续就要浮点，浮点就跨平台不一致。

所以这道题的全部工程价值在一个问题上：**能不能用纯整数把弹道算准，并且两个平台算出同一条弧线**。

## 2. 定点物理怎么做的

| 项 | 做法 |
|---|---|
| 数值格式 | Q16.16（1.0 = 65536），位置/速度/加速度全部 `int64_t` |
| 三角函数 | `trig.hpp` 里 181 项编译期常量表；端点 0/90/180 手工钉死 |
| 积分 | `v += a; x += v`，每 tick |
| 碰撞 | 起点→终点线性插值 + 动态子步（每子步 ≤ 0.25 格） |
| 禁止项 | `float` / `double` / `sin` / `cos` / `rand` / 系统时间，一个不用 |

动态子步是关键：规则原文写"用 4 个子步"，但重力会让速度超过 1 格/tick，固定 4 步会穿墙。改成 `1 + max(|vx|,|vy|) / 0.25`，纯整数，仍然确定。

## 3. 这一轮真正花时间的地方：地图

生成器改了四轮，前三轮失败模式完全一样——**虫被埋在土里，打不出去**。

```
v1  空气 55%，虫头顶 4 格空气    → 45° 射击 3 格即撞土
v2  加天空 y<17 + 平台打 14 格   → 空气 44.6% 压线，但土柱把虫卡住
v3  天空压到 y<22               → 空气 53–56% 超上限，仍被卡住
v4  出生点抬到 y26–33（近地表）  → greedy 首轮命中 (83,27)
```

**诊断手段**：给 greedy 加 `P01_DEBUG` 环境变量，打印每轮 `simulate()` 的命中坐标。

第一次跑出来是这样：

```
r1 best=0 a=0  p=23 hit=(15,34) me=(12,33) foe=(83,33)
r3 best=0 a=78 p=71 hit=(17,30) me=(16,33) foe=(83,33)
```

`best=0` 表示 1600 多个候选里没有一个能打中。`hit=(17,30)` 说明 78° 斜射撞在右上方三格的土柱上。

没有这个输出，只会看到"greedy 打不中"，完全看不出是"撞土"还是"物理算错"。

**教训**：弹道类题目的地图不是"能站人"就行，得有**射击仰角**。这条写进了 RULES C7，空气比例上限从 45% 放宽到 60%。

## 4. 修掉的七个规则问题

| # | 问题 | 修正 |
|---|---|---|
| C1 | 协议是 `GAME BALLISTIC` + 多行指令 | 统一成 `INIT`/`TURN` + 单行 `;` 分隔 |
| C2 | `speed = power * 655` | 改 `power * 65536 / 100`，否则 power=100 得 65500 不是 1.0 |
| C3 | 固定 4 子步 | 改动态子步，防止高速穿墙 |
| C4 | 引擎输出 `RESULT` | 改由裁判从终局状态读，避免两处各算一次胜负 |
| C5 | 未定义"同时落水" | 按虫 id 升序结算 |
| C6 | 手雷停住后永久静止 | 停住仍受重力，支撑被炸掉就继续掉 |
| C7 | 空气比例 25–45% | 放宽到 25–60%，否则虫必被埋 |

## 5. 验收

| 项 | 结果 |
|---|---|
| 引擎编译 | 通过 |
| 完整对局 | 三种对阵全部跑满 40 轮 |
| greedy vs random | 3–0，greedy 满血 300 |
| template vs random | 3–0，284 对 265–300 |
| **greedy vs template** | **3–0，3/3 全灭，greedy 满血 300** |
| 打包 | 13 文件，两次 hash 一致 |
| 泄漏 | 0 fail 0 warn |

greedy 与 template 的唯一差别：前者用 `simulate()` 枚举 61 角度 × 27 力度。就这一条，结果从"打不中"变成"场场全灭且不掉血"。

## 6. 遗留

| # | 问题 |
|---|---|
| R1 | 样本只有 3 局/组，只能看趋势 |
| R2 | `scripted`（挖地形/占高台）未实现，只有三档基准 |
| R3 | **跨平台确定性**——本题核心目标。原记录"只在 Windows 跑过"；2026-11-02 已用 WSL Ubuntu 补验，54/54 `state_hash` 一致 |
| R4 | 计时是 wall clock |
| R5 | 没有 fuzz 和 golden 测试，边界用例只做了手动抽查 |

R3 是最要紧的：这道题存在的意义就是证明"定点物理可以跨平台复现"。不验证这一点，它的价值只兑现了一半。

## 7. 一句话

引擎 900 行，地图生成器改四轮。难点不在物理公式，在**给物理留出表演空间**。
