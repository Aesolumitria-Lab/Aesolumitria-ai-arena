# P01 地图分类（类型轴）与"分类生存"读数

> **现行是 v2.4.3：两个轴（`cover` × `elevation` = 9 种组合，每种 12 张）。**
> 本文件记录的 v2.4.0 三轴（27 种）历史与读数保留，但 `openness` 已在 v2.4.3 删除 ——
> 原因与读数见 §3.3 与 `known-issues.md`。下面凡是写着「27 种 / 每种 4 张」的段落，
> 都是 **v2.4.0/v2.4.2 当时的口径**，现行是 **9 种 / 每种 12 张**。

> 全部读数可用 `problems/p01-ballistic/tools/genmap_p01_types.py` + `problems/p01-ballistic/tools/p01_fairness_audit.py` 复现。
> 这一版**只动地图，不动引擎、不动规则数值**。

## 0. 问题：108 张图其实是同一张图

v2.2.0 的 mirror4 解决了**公平性**（严格镜像、四席等高等距、0 张单座垄断），
但没解决**多样性**。实测（旧 108 张）：

| 指标 | 旧 mirror4 |
|---|---|
| 两两格差 | **均值 1.66%**（最大 4.13%） |
| 台面到水面 | **恒为 21**（1 种取值） |
| 上半屏空气 | sd **1.20%**（94.2–98.8%） |
| 几何轴 vs 胜率的相关 | \|r\| 全部 **< 0.15** |
| 公开 vs 隐藏的格差 | 1.72%（≈ 公开内部 1.44% / 隐藏内部 1.73%） |

⇒ 隐藏图只是"同分布的另一批 seed"，测不出泛化；也没有任何"类型"可分。

## 1. 当初加了三个正交类型轴（全部保持镜像对称）—— v2.4.3 删掉了 openness

| 轴 | 档 | 含义 |
|---|---|---|
| `openness` | `open` / `mound` / `wall` | 中央无遮挡 / 可破坏土丘（`#`，能挖穿）/ 永久基岩柱（`X`） |
| `cover` | `bare` / `flank` / `flank+canopy` | 无 / 席间矮掩体 / 矮掩体 + 四席同规短檐 |
| `elevation` | `mesa` / `level` / `basin` | 台面 y=26（高台）/ 30（平地）/ 34（洼地） |

**3 × 3 × 3 = 27 种组合**。公开 108 张 = 每种 **4 张**（按 `i % 27` 交错，
所以前 27 张就覆盖全部类型）；隐藏 108 张同类型、不同 seed（公开图 seed 3000–3107；隐藏图由不公开的私有 seed 生成）。

三个轴都作用在**四席共有**的属性上（同一 y、同一半宽、同一檐宽），
不会让某一席单独变高/变矮/多檐 —— 公平性与 v2.2.0 一致，`validate4` 的镜像检查仍全过。

## 2. 多样性真的上去了

| 指标 | 旧 mirror4 | 新 27 类型（v2.4.0 初版） | 新 27 类型（**v2.4.2 去重后，现行**） |
|---|---|---|---|
| 两两格差 | 1.61% | 7.75%（最大 19.3%） | **8.48%**（最大 19.75%，n=5778） |
| 类型内格差 | — | 1.13% | **2.38%** |
| 类型间格差 | — | 8.11%（比值 7.19×） | **8.65%（比值 3.64×）** |

> **★ v2.4.2 为什么「类型间/类型内」从 7.19× 掉到 3.64×，而这不是回退。**
>
> v2.4.0 的那个 1.13% 是**假的**：`openness=open` 与 `cover=bare` 两档不消耗随机数，
> `elevation` 只改 `base_y`，于是 `open|bare|*` 三类图是 seed 无关的纯函数 —— 每种 4 张
> 里其实是**同一张抄了 4 份**（实测 sha256 完全相同）。类型内距离小，是因为它们本来就是同一张图。
>
> v2.4.2 给生成器加了 `surface_texture()`（只改形、不改类：地表 ±1~2 格 + 地下空腔，成对镜像写入），
> 四种图真的不一样了，**类型内距离自然涨到 2.38%**。所以 3.64× 是诚实读数，7.19× 分母被压小过。
> 同一轮还修掉了隐藏图与公开图逐字节重复（旧集 25/108 撞图，新集 0 张）。
| 头顶净空 | 5 种取值组合 | **9 种**（且四席完全相同，mean 12.7） |
| 中央障碍最高点 | 25–27 | **20–34**（14 种取值） |
| 掩体量取值组合 | 75 | 79 |
| 上半屏空气 | sd 1.20% | sd **6.81%**（78.7–100%） |
| 台面到水面 | 恒 21 | 17 / 21 / 25（三档高程） |

## 3. "分类生存"读数：行为和胜者是两回事

两个读数分开看，因为它们结论不同。

### 3.1 行为层：类型确实分开了

用 4 档 bot（hard/normal/easy/random）跑每图 24 排列，从 replay 读出
`rounds / 挖掉的格子数 / 终局 HP 总和 / 总伤害`，按类型汇总：

| | 值 |
|---|---|
| 跨类型行为距离 | **0.372** |
| 类型内行为距离 | **0.189** |
| 比值 | **1.96×** ⇒ 类型在行为上确实不同 |

典型例子（54 张原型图的读数）：

- `mound|bare|basin`：26.4 回合、终局 HP 总和 67.6（打得快、打得狠）
- `mound|flank+canopy|basin`：**35.8 回合**、终局 HP 总和 **361.9**（掩体多 ⇒ 拖长、打不动）
- `open|bare|mesa`：26.1 回合、HP 总和 41.8（最裸、最快分出胜负）

### 3.2 胜者层：4 档基准 bot 的胜率几乎不受类型影响

跨类型胜者剖面距离 **0.052**，类型内 **0.083** ⇒ 比值 **0.63**，反而**没**分开。

单轴效应（把其他两轴平均掉，n=1728/档）：

| 轴 | 档位 | hard / normal / easy / random |
|---|---|---|
| openness | mound / open / wall | 44.0 / 42.8 / 42.9（hard），差异 **< 1.2pp** |
| cover | bare / flank / flank+canopy | 45.2 / 40.7 / 43.9（hard），差异 **4.5pp** |
| elevation | basin / level / mesa | 42.8 / 43.3 / 43.6（hard），差异 **0.8pp** |

⇒ **TIDE 这几档 bot 已经足够"全能"，地图类型改不了谁赢。**
这不是缺陷，是"基准够强"的正常表现；但如果想用地图类型做排名分层，
**用"谁赢"当读数是不够的**。

### 3.3 用专精探针 bot 才能看出类型的作用

造了两个只做一件事的探针（探针源码（未随仓库发布），编译期开关）：

- `SPEC_LOB`：不看地形，永远 79°/101° 最大仰角抛射
- `SPEC_TUNNEL`：能挖就钻（DRILL）、挖不动就走、走不动就贴脸低角度

4 席对局（席 0/2 用 LOB、席 1/3 用 TUNNEL，随 24 排列轮换），2592 局：

| 轴 | 档位 | LOB 占比 | spread |
|---|---|---|---|
| `cover` | bare 66.7% / flank 92.6% / flank+canopy 93.7% | | **27.0 pp** |
| `elevation` | mesa 74.7% / level 85.5% / basin **100%** | | **25.3 pp** |
| `openness` | open 85.3% / mound 86.5% / wall 85.1% | | **1.4 pp** |

⇒ **cover 与 elevation 两个轴对"策略是否可行"有 25–27pp 的影响**，
而 **openness 几乎没影响（1.4pp）**。

openness 弱的原因很具体：中央土丘/基岩柱挡的是**地面行进**，
但这题的主流打法是**高抛**，高抛直接飞过中央障碍；能挡高抛的只有
"头顶的檐"（canopy），那是 cover 轴的活。

**⇒ v2.4.3 的处理是「删掉它」，不是「想办法救它」（2026-11-10 已确认）。**

理由：要让它真的起作用，就得让它挡天空（中央悬空平台 / 天花板），
那是**重新设计地图机制**，不是调一个轴；而它现在占着三分之一的组合（27 → 9），
等于用 2/3 的图集换来一个测不出效应的轴。
**删掉之后图集反而更好读**：9 种类型、每种 12 张，同类型内样本从 4 张涨到 12 张。

（`sky-design.md` 里试过「挡天空」那一版，实测偏向读数不成立 ——
端点方向随探针参数翻转，那是「指标不成立」而不是「效应太小」，所以也没并入。）

## 4. 关于"分类生存"的结论

1. **类型分出来了**（v2.4.0 时是 27 种；v2.4.3 起 9 种，几何与行为上的分离读数保留在 §2/§3）。
2. **基准 bot 的排名不随类型变**（<5pp），所以"用类型做 ELO 分层"目前**没有数据支撑**。
3. **策略专精度随类型变**（cover/elevation 上 25–27pp），所以
   `rating4` 值得加一个**按类型分组的胜率表**：不是为了让基准分层，
   是为了让选手看到"我这个打法在哪类图上会崩"。

## 5. 复现

公开图可用下面的命令重生成（隐藏图由不公开的私有 seed 生成，命令不在此列出）：


```bash

```


## 6. 落地摘要（原单独摘要文档并入）

- 现行口径（v2.4.3）：**2 个轴 / 9 种组合 / 每种 12 张**；`openness` 已删除。
- 公开 108 张 = 每种 12 张；隐藏 108 张同类型、不同 seed，公开与隐藏零重叠。
- 公平性与 v2.2.0 一致：四席等高等距、严格镜像（0↔3 / 1↔2）。
- 关键读数：两两格差 v2.2.0 1.61% -> v2.4.2 8.48%；类型间/类型内格差 3.64x；上半屏空气 sd 1.20% -> 6.81%；台面到水面 17 / 21 / 25。
- 行为层跨类型/类型内 1.96x（类型真的分开了）；胜者层 4 档基准 bot 胜率极差 <5pp（类型改不了谁赢）；策略层 `cover` 27.0pp、`elevation` 25.3pp、`openness` 1.4pp。
- 「挡天空」方向的实验见 [`sky-design.md`](sky-design.md)。
