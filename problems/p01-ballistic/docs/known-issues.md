## 2. 2 席 vs 4 席

结论：保留 4 席，不改 2 席。三条硬事实：

1. 2 席模式要求 legacy 镜像图：`active_mask=0b0011` 下引擎 strict LOAD 会拒掉任何 maps4 图（报 `map is not mirror symmetric`，maps4 是 0↔3 / 1↔2 镜像，不是 0↔1）。现存 legacy 2 席图只有 3 张。
2. 判官栈是另一套：`judge4.play_one()` 是 4 席专用，2 席走 `judge.play_match()`（两局换座位）。
3. 改成 2 席意味着丢掉 216 张 maps4、整套 4 席座位轮换设计和全部 4 席读数，外加换一套判官，是推倒重来。

同一批 TIDE-NORMAL 自战的实测读数：

| 格式 | 图 | 局数 | 座次分布 | 备注 |
|---|---|---|---|---|
| 2 席 | legacy x3 | 24 | [0, 24] | 两局换座位后仍全由 seat1 赢，2 席只剩两个标签，座位差直接变成 100% |
| 4 席 | maps4 x12 | 576 | [38.5, 6.2, 6.9, 48.3] | 12/12 张图有多个座次赢过 |

4 席座次分布看起来更不均，但那是四个标签摊掉的结果；2 席把同样大小的标签差压进两个格子，反而是结构性 100%。2 席不是更公平，是更脆。复现工具：`problems/p01-ballistic/tools/p01_2vs4.py`（读数数据在 `data/2vs4.json`）。

## 3. 「内席劣势 / 该不该补偿」的结论

完整实测见 [`fairness-audit.md`](fairness-audit.md) §3.1b / §3.1c / §3.5。

| 问题 | 答案 |
|---|---|
| 内席（1/2）真的吃亏吗 | 是。阵亡率 91% / 95% vs 外席 71% / 60%（1.42 倍），64 局实测 |
| 原因是「被炸到更深、离水更近」吗 | 不是。终局地表只低 0.49 行，虫平均 y 只低 0.20 行；609 条死亡里淹死 0 条 |
| 真实原因 | 直击：两面夹击，挨打更多，掉血死。与水位无关 |
| 座位本身值多少 | 外席 30.6% / 39.6%，内席 14.2% / 15.6%（4 个不同 bot，288 局） |
| 不轮换会怎样 | 同一个 bot 换座，胜率从 19.4% 到 68.1%（tide_normal：seat1 vs seat3） |
| 污染 benchmark 了吗 | 没有。四个固定座位各自给的排序与正式赛制一致 |

补偿方案状态：血量补偿要动引擎（会让图集、用例和 hash 对账全部作废），实验用 scratch 引擎，未并入；护盾在引擎里没有概念，是新机制不是参数；3D / 2x2 摆位不采用（侧视 2D + 全局水平涨水要求座位同高）。
