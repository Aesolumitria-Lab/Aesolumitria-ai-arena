# P01 BALLISTIC · 设计笔记（来自 v0.1 规则设计稿）

> **现行规则以 [`../RULES.md`](../RULES.md) 为准。**
> 本文只保留 v0.1 设计稿里至今仍然成立的设计动机。v0.1 稿中的具体规则细节（1v1、每方 3 条虫的 3 席假设、首步 2000 ms CPU、seed 位平局、greedy/scripted 基准、v0.2/v0.3 路线图等）已与现行规则冲突或被取代，这里一律不再收录。版本号与各项 hash 以 `../meta.json` 为准。

## 1. 这道题想验证什么

P01 是题库里的“冒烟题”：没有部分信息，引擎最小，用来验证平台的几件基础设施：

- 定点物理与确定性（同一份输入在不同平台得到同一条弹道）；
- 回放与逐状态 hash 对账；
- 计时与判罚；
- 打包与选手自检。

它的工程价值集中在一个问题上：能不能用纯整数把弹道算准，并且跨平台一致（实现经过见 [`implementation-report.md`](implementation-report.md)，跨平台读数见 [`crossplatform-and-host-speed.md`](crossplatform-and-host-speed.md)）。

## 2. 仍然有效的设计动机

| 设计选择 | 动机 |
|---|---|
| 全程定点（Q16.16）、三角函数查表、禁用 `float` / `double` / libm / 随机 / 系统时间 | 浮点和 libm 在不同机器上结果可能不同，会让回放对不上、排名有争议 |
| 碰撞用动态子步（每子步位移不超过 0.25 格） | 重力会让速度超过 1 格/tick，固定子步数会穿墙；动态子步是纯整数运算，仍然确定 |
| 地形可破坏，地图外圈基岩 | 挖地、掩体、落水构成战术空间 |
| 全信息 | 地形、位置、血量、弹药、风、水位全部公开，没有隐藏信息问题 |
| 风序列与随机性只来自 seed | 任何一局都能由 (地图, seed, 双方动作) 完整重放 |
| 涨水 + 40 轮上限 | 防止互相挖坑拖满时间；水位只降到一个有限的下限，不会淹没整张图 |
| 地图必须留射击仰角 | 弹道题的地图不是“能站人”就行；空气比例上限曾从 45% 放宽到 60%（RULES 第 23 节 C7）。后续类型轴设计见 [`map-types.md`](map-types.md) |
| 地图严格镜像、座位轮换 | 用对称与轮换抵消先后手/座位偏差；现行的 4 席版本与实测见 [`fairness-audit.md`](fairness-audit.md) |
| 由裁判而不是引擎读取终局结果 | 避免引擎与裁判各算一次胜负、出现分歧时无法定位 |
| 基准 bot 做“可解释的尺子”，强度分档 | 现行梯队是 TIDE 三档加三个挑战 bot，见 [`../BOT_LADDER.md`](../BOT_LADDER.md) |

## 3. 设计稿里的风险清单（仍可参考）

| 风险 | 对策 |
|---|---|
| 浮点物理跨机器不一致 | 定点 + 查表（已落地并跨平台验证） |
| 投射物穿墙 | 动态子步 |
| 手雷反弹抖动 | 速度阈值 + 位置回退；黄金轨迹测试 |
| 互相挖坑拖时间 | 涨水 + 40 轮上限 |
| 50 ms 不够搜索 | 现行做法是按参考机换算的 CPU 预算，见 RULES 第 15 节 |
| 地图不公平 | 镜像 + 座位互换统计；现行做法见 `fairness-audit.md` |
| 虫被地形埋住 | 地图生成保证出生点连通；加载时严格校验 |

## 4. 与现行规则的主要差异

| 项 | v0.1 设计稿 | 现行 |
|---|---|---|
| 席位 | 1v1 | 2–4 席，4 席为主要模式 |
| 首步预算 | 2000 ms CPU | 首步 2 s 墙钟宽限，CPU 预算按参考机换算 |
| 平局 | 最后用 seed 位决定 | 血量、总伤害、存活数仍相同则判平局，不用 seed 决定胜负 |
| 地图 | 水平镜像、3 + 3 张 | 4 席 mirror4 构造族 + 类型轴，公开 108 张 / 隐藏 108 张 |
| 基准 | random / greedy / scripted | TIDE 三档 + CHIMERA / PSEUDO / TYPHON |
